# Spec: packaging

## Objective
Produce a distributable Windows product: a single NSIS installer that installs
the app **per-user** (no UAC), bundles the yt-dlp + ffmpeg binaries, and lays
down a writable install folder so `config.json` can live next to the exe.

## Tech Stack
Wails v2 (**≥ v2.13.0 required — see below**), NSIS 3.x (`makensis`), Wails asset
embedding.

> **Version requirement (verified against Wails source).** The `-installscope`
> flag and the `${WAILS_INSTALL_SCOPE}` handling in the NSIS template were added
> in **v2.13.0**. Wails **v2.12.0 does not have them** — its `project.nsi` hardcodes
> `InstallDir "$PROGRAMFILES64\..."` and `RequestExecutionLevel admin`.
> **Action:** upgrade the Wails CLI + module to the latest v2 (v2.16.0 at time of
> writing) before Task 15. Verify with `wails build --help | grep installscope`.

## Commands
- Dev build: `wails build -debug`
- Release build + installer: `wails build -nsis -clean -platform windows/amd64 -installscope user`
- Verify binary: `build/bin/VideoDownloader.exe`
- Verify installer: `build/bin/*-installer.exe`

## Project Structure
```
resources/                     → bundled yt-dlp.exe, ffmpeg.exe, ffprobe.exe
build/windows/installer/
  project.nsi                  → NSIS script — WE EDIT THIS (compressor + File lines)
  wails_tools.nsh              → generated by Wails each build (do not hand-edit)
  info.json                    → product metadata (name, company, version)
  tmp/MicrosoftEdgeWebview2Setup.exe → written by Wails
wails.json                     → "info" block feeds installer/info.json
```

## Distribution Decision (resolved)
**One installer, everything included.** No "Full/Lite" variants, no component
checkboxes. Both `yt-dlp.exe` and `ffmpeg.exe`/`ffprobe.exe` are always shipped.

- Rationale: simplest possible user experience — one download, one click, it just
  works. MP3 conversion and video+audio merging **require** ffmpeg, so making it
  optional only creates broken states to explain.
- Size: the binaries are ~212 MB on disk; with **LZMA solid** compression the
  installer lands around **65–75 MB**. Acceptable for a one-time download.
- Consequence: the engine never needs a "ffmpeg missing → install it" flow. It
  still checks binary presence at startup and reports a clear error if a file is
  somehow absent (e.g. user deleted it), but this is a corruption case, not a
  supported configuration.

## Bundled Binaries — HOW they get into the installer
Wails' built-in `wails.files` macro **only embeds the application exe** (verified:
it emits a single `File "/oname=${PRODUCT_EXECUTABLE}" ...`). Extra binaries must
be added **by us** to `build/windows/installer/project.nsi`.

- Wails writes `project.nsi` **only if it does not already exist** (verified in
  `nsis_installer.go`: it reads the file and writes the template on error/absence).
  Therefore our edits to `project.nsi` are **preserved** across builds — but the
  file must be committed to the repo.
- Add the three binaries to the main install section, after
  `!insertmacro wails.files`:
  ```nsis
  SetOutPath $INSTDIR
  !insertmacro wails.files          ; the app exe
  File "..\..\..\resources\yt-dlp.exe"
  File "..\..\..\resources\ffmpeg.exe"
  File "..\..\..\resources\ffprobe.exe"
  ```
  (Paths are relative to `build/windows/installer/`; confirm the exact depth when
  Task 15 runs — adjust so `makensis` resolves them.)
- They are resolved at runtime from the **exe directory**, matching `Bins` in the
  `ytdlp-engine` spec.

## Installer Configuration
- **Install scope: user** — pass `-installscope user` on the build command. Wails
  then defines `WAILS_INSTALL_SCOPE=user` + `REQUEST_EXECUTION_LEVEL=user`, so the
  template sets `InstallDir "$LOCALAPPDATA\Programs\${INFO_PRODUCTNAME}"` and the
  uninstall registry entries go to **HKCU** (no admin, no UAC). This is what makes
  the in-install-folder `config.json` writable.
- **Compression: LZMA solid — must be added by us.** The Wails default
  `project.nsi` contains **no `SetCompressor`** (verified), so NSIS defaults to
  **zlib**, which will *not* reach the 65–75 MB target. Add near the top of
  `project.nsi`:
  ```nsis
  SetCompressor /SOLID lzma
  SetCompressorDictSize 64   ; MB; raise if useful, keep modest for RAM at install
  ```
- **No components page.** Do not insert `MUI_PAGE_COMPONENTS`; there are no
  optional sections. All `File` directives live in the single mandatory section.
- Include an uninstaller (Wails default) and register the app in "Apps & features".
- Product metadata (name, company, version, copyright) sourced from `wails.json`
  `info` → `installer/info.json`.
- Ship the WebView2 bootstrapper (Wails default) so first-run works on machines
  without WebView2.

## Testing Strategy
- `wails build -nsis -installscope user` completes with exit 0 and emits both the
  exe and the installer.
- Confirm the installer is **LZMA-compressed** (size ~65–75 MB, not ~200 MB).
- Install on a clean Windows account: **no UAC prompt**; app launches;
  `config.json` is created in `$LOCALAPPDATA\Programs\...`.
- Download a YouTube URL and a non-YouTube URL; download a video and an MP3
  (proves the bundled ffmpeg is found).
- Uninstall from "Apps & features": program + `config.json`/`history.json` gone,
  downloaded media untouched.
- Verify no `makensis not found` warning (NSIS on PATH).

## Boundaries
- **Always:** pin the Wails version in `wails.json`/`go.mod` (≥ v2.13.0); commit
  `project.nsi`; rebuild binaries into `resources/` via a documented step (never
  commit a stale `yt-dlp.exe` silently).
- **Ask first:** switching to machine-wide scope; code-signing the exe/installer;
  changing the install directory layout.
- **Never:** require admin rights for a normal install; write app config into
  `Program Files`; ship without the WebView2 bootstrapper; rely on the Wails
  default compressor (zlib) — it misses the size target.

## Success Criteria
- [ ] Wails CLI/module upgraded to **≥ v2.13.0** (v2.16.0+ recommended).
- [ ] `wails build -nsis -installscope user` produces `build/bin/*-installer.exe`.
- [ ] Installer installs per-user with **no UAC prompt** (`$LOCALAPPDATA\Programs\...`).
- [ ] Installer is **LZMA-compressed** and lands in the ~65–75 MB range.
- [ ] No components page appears (single mandatory install, no checkboxes).
- [ ] All three binaries (`yt-dlp`, `ffmpeg`, `ffprobe`) are installed next to the exe.
- [ ] Installed app finds the bundled binaries and downloads a video **and** an MP3.
- [ ] `config.json` is created inside the install folder.
- [ ] Uninstaller runs cleanly from "Apps & features" and removes `config.json`/`history.json`.

## Uninstall Behaviour
- Wails' uninstaller does `RMDir /r "$INSTDIR"`, which removes the whole install
  folder **including `config.json` and `history.json`** — this matches the decided
  behaviour (clean uninstall, no leftover app state). Downloaded media in the
  user's chosen download folder is **never** touched.
